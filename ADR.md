# Рішення: [Events tracking] 
## Контекст 
Потрібно було створити систему збору та аналізу подій (event ingestion and analytics), 
яка здатна обробляти великий обсяг даних (100k+ подій), 
забезпечувати швидкі аналітичні запити та масштабуватися в майбутньому. 

Основні виклики:

- Швидкий запис великої кількості подій
- Ефективні аналітичні запити (DAU, top events, retention)
- Ідемпотентність операцій
- Асинхронна обробка для масштабування
- Балансування між швидкістю запису та читання

## Рішення 1: Веб-фреймворк
### Варіанти

**Варіант A: FastAPI**

*Плюси:*
- Нативна підтримка async/await для високої продуктивності
- Автоматична генерація OpenAPI документації
- Вбудована валідація через Pydantic
- Попередній досвід роботи з фреймворком
- Легка інтеграція з SQLAlchemy async
- Dependency Injection з коробки

*Мінуси:*
- Менше готових бібліотек для складних кейсів
- Менше ресурсів з ком'юніті порівняно з джанго

**Варіант В: Django + Django REST Framework**

*Плюси:*
- Вбудована admin панель
- ORM з коробки
- Багато готових рішень для auth, permissions

*Мінуси:*
- Повільніший за FastAPI для async операцій
- Складніше налаштування async views
- Більший overhead для простого API

**Варіант C: Flask + Flask-RESTful**

*Мінуси:*
- Немає досвіду роботи з Flask, тому було б довше все для розуміння

## Рішення 2: Hot Storage


**Варіант A: PostgreSQL**

*Плюси:*
- Відмінний попередній досвід роботи
- ACID гарантії для критичних операцій
- Чудова інтеграція з SQLAlchemy
- Ефективні індекси (B-tree, GiST, GIN)

*Мінуси:*
- Не оптимізована для аналітичних запитів
- Row-oriented storage менш ефективний для aggregations
- Потребує більше ресурсів при великих обсягах даних


**Варіант В: MongoDB (NoSQL)**

*Плюси:*
- Гнучка схема для різних типів events
- Нативна підтримка JSON
- Горизонтальне масштабування

*Мінуси:*
- ❌ Немає попереднього досвіду
- ❌ Важче інтегрувати з SQLAlchemy

## Рішення 3: Cold Storage

### Варіанти

**Варіант A: DuckDB**
*Плюси:*
- SQL-сумісна, працює з SQLAlchemy (через duckdb-engine)
- Стовпчикове зберігання - ефективна компресія
- Легка інтеграція в існуючу інфраструктуру
- Рекомендовано в завданні - можливість вивчити щось нове

*Мінуси:*
- Менша підтримка SQLAlchemy порівняно з PostgreSQL
- Обмежена concurrency для writes


**Варіант B: ClickHouse**

*Плюси:*
- Найпотужніша OLAP база даних
- Надзвичайно швидкі аналітичні запити
- Багато інтеграцій та інструментів

*Мінуси:*
- Потребує окремого сервера
- Складніше налаштування та підтримка
- Overkill для поточного масштабу проекту
- Більше часу на вивчення
